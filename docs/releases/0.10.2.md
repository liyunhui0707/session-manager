# 0.10.2 release verification

## Subsequent browser-install failure

A real browser download and Finder installation on macOS 26.6.2 ARM64 exposed
a first-launch failure: macOS reported the app as damaged. The DMG and installed
ASAR matched the published hashes, but strict bundle signature verification
failed: `code has no resources but signature indicates they must be present`.
The original local release bundle reproduces the failure. The earlier checks
below did not cover this path. Do not bypass system protections to run this
release; corrected packaging and renewed first-launch acceptance are required.

## Distribution

Apple Silicon (ARM64), macOS 12 or later. This is an unsigned, unnotarized
release. Installation and updates are manual; see [installation](../installation.md).
Minimum OS is a declared requirement, not a claim of testing every OS version.

This patch fixes Electron runtime preparation in fresh source checkouts, refuses
existing same-version artifacts before packaging, and updates Electron to 43.8.7
and electron-builder to 26.18.0. Reader features are unchanged.

## Executed checks

- Clean source installation and 691 application tests passed.
- Eight release-tool tests passed, including regression coverage for the build failure.
- Apple Silicon DMG verification and ZIP integrity checks passed.
- On macOS 27.2 ARM64 and macOS 26.6.2 ARM64, each machine passed 146 packaged reader checks and 20 restart/replacement checks across three launches.
- The replacement sequence used 0.10.1, restarted it normally, then replaced it with 0.10.2 at the same isolated path. Source selection, favorites, 26 px font, theme and width survived. Synthetic content remained readable and unchanged. Test processes exited normally without remaining process groups.
- GitHub CI passed public-tree scanning, release tools, dependency audits, application tests and unsigned Intel packaging. Intel interactive acceptance has not been performed; no Intel download is published.
- Current public-tree privacy scanning found no flagged content. This is a bounded scan, not a guarantee of complete secret detection.
- Dependency audits report zero production findings and zero high/critical findings in the full tree. Six moderate build dependency entries remain; see [assessment](../dependency-audit.md).

## Evidence limits

The second Mac received hash-verified packages through SSH because its GitHub
download timed out. These runs verify application behavior and controlled bundle
replacement, not a browser-quarantined download, Finder drag installation, or
Gatekeeper's first-open flow. No system protection was disabled and no daily
installation was replaced.

The initial local runtime download failed. The official Electron archive was
obtained through the existing system proxy, checked against the locked package's
SHA-256, and supplied through an isolated installer cache. A completely uncached
direct-network download was not demonstrated locally.

The maintainer confirmed that the public website displays in a normal browser.
Automated browser checks were unavailable; command-line requests were rejected
by Cloudflare. Static links/assets were checked. Mobile interactions and a full
browser download/install journey were not verified this round.
